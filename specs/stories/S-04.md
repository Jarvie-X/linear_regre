# S-04 — Present understandable results

## Technical implementation spec

### Goal

Present a completed held-out regression run as a short, non-technical result
summary. The summary must make the data load, evaluation measures, and the
difference between sample predictions and actual outcomes visible without
requiring readers to inspect Python or scikit-learn details.

### Design

- Add a `ResultSummary` value containing the dataset counts, held-out
  `PredictionQuality`, and a configurable set of prediction/actual sample
  pairs. The default presentation includes five pairs (or all pairs when the
  evaluation set contains fewer than five) and validates that each pair comes
  from the same held-out result.
- Add `summarize_results` to build that value from `DiabetesDataset`,
  `TrainedRegression`, and `PredictionQuality`, and add
  `format_result_summary` to render it as readable plain text. Values are
  rounded for display while calculations continue to use the full precision
  measures.
- Update the input-free module workflow to print the formatted summary after
  loading, training, and evaluating. It will explicitly label the examples as
  held-out, explain MAE and R² in plain language, and state that the result is
  for teaching/demonstration only—not automated decision-making.
- Preserve the existing lower-level preparation, training, and measurement
  APIs. The presentation layer consumes their results and does not use
  training-set scores or imply clinical/operational use of the Diabetes data.

### Validation

Tests will verify that the default output contains at least five prediction /
actual rows, includes the load confirmation and all key measures, explains
quality in plain language, includes the teaching-only disclaimer, and rejects
inconsistent or empty result inputs.

### Verification command

```sh
PYTHONPATH=src python -m linear_regre.diabetes
python -m pytest
```
