# S-05 — Verify repeatable end-to-end workflow

## Technical implementation spec

### Goal

Provide a complete, input-free Diabetes regression workflow that can be run
repeatedly from dataset loading through human-readable held-out results.

### Design

- Add one `run_workflow` orchestration function that prepares the built-in
  scikit-learn Diabetes dataset, trains the regression model, measures
  held-out prediction quality, and builds the presentation-ready summary.
- Keep the workflow deterministic by using the existing fixed dataset split
  and no customer file, prompt, or external service. Each invocation returns
  an independent `ResultSummary` with at least five prediction/actual rows.
- Make the module command invoke that orchestration function and print the
  complete formatted result. The existing summary's held-out labels,
  evaluation metrics, and teaching-only disclaimer provide the human review
  surface required before demonstration or decision-making.

### Validation

Tests will execute the complete command twice without stdin, assert both runs
finish successfully with identical output, and verify each output includes the
dataset-load confirmation, held-out evaluation measures, at least five
prediction-versus-actual examples, and the human-review disclaimer. Existing
unit tests continue to cover each workflow stage and reject incomplete data.

### Verification command

```sh
PYTHONPATH=src python -m linear_regre.diabetes > /tmp/s05-run-1.txt
PYTHONPATH=src python -m linear_regre.diabetes > /tmp/s05-run-2.txt
cmp /tmp/s05-run-1.txt /tmp/s05-run-2.txt
python -m pytest
```
